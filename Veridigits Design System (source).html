01 · Brand

Quiet, anonymous, technical.

Veridigits sits in a category that's loud, scammy, and full of neon. Our positioning is the opposite — a piece of infrastructure that recedes. The wordmark sits on warm paper. The accent is used sparingly, only where verification has happened. Numbers always speak in monospace. Sentences stay short.

06 · Implementation

Drop into Claude Code.

Two files do all the work: app/globals.css for the CSS variable layer, and tailwind.config.ts for the theme extension. The variable names follow the --background / --foreground / --primary convention so any UI primitive library can consume them with no extra wiring.

app/globals.css
/* Veridigits tokens — light only */
@layer base {
  :root {
    /* surfaces */
    --background: #FAF8F3;   /* paper */
    --foreground: #14110C;   /* ink */
    --card: #FFFFFF;
    --card-foreground: #14110C;
    --popover: #FFFFFF;
    --popover-foreground: #14110C;
    --muted: #F2EFE8;
    --muted-foreground: #6B6558;
    --border: #E2DED2;
    --input: #C8C2B1;

    /* primary = verification green */
    --primary: #00C46A;
    --primary-foreground: #14110C;

    /* secondary = ink (high-contrast CTA) */
    --secondary: #14110C;
    --secondary-foreground: #FAF8F3;

    --accent: #ECFAF0;
    --accent-foreground: #00854A;

    --destructive: #D43F3F;
    --destructive-foreground: #FFFFFF;

    --ring: #00C46A;
    --radius: 0.625rem; /* 10px = md */
  }

  html, body {
    font-family: "Aeonik", "General Sans", ui-sans-serif, system-ui;
    font-feature-settings: "ss01", "cv11";
  }
}
tailwind.config.ts
import type { Config } from "tailwindcss";

export default {
  content: ["./app/**/*.{ts,tsx}", "./components/**/*.{ts,tsx}"],
  theme: {
    extend: {
      fontFamily: {
        sans: ["Aeonik", "General Sans", "ui-sans-serif"],
        mono: ["JetBrains Mono", "ui-monospace"],
      },
      colors: {
        // semantic aliases — all reference --vars from globals.css
        background: "hsl(var(--background))",
        foreground: "hsl(var(--foreground))",
        primary: {
          DEFAULT: "#00C46A",
          foreground: "#14110C",
        },
        // brand-specific scale, used in domain components
        vg: {
          50: "#ECFAF0", 100: "#D5F4DF",
          200: "#A8E8BE", 300: "#6ED593",
          500: "#00C46A", 600: "#00A85B",
          700: "#00854A", 900: "#0A3D26",
        },
        paper: "#FAF8F3",
        ink: { DEFAULT: "#14110C", 2: "#3A3630", muted: "#6B6558" },
      },
      borderRadius: {
        md: "10px", lg: "14px", xl: "20px",
      },
      boxShadow: {
        card: "0 1px 0 rgba(20,17,12,.04), 0 1px 2px rgba(20,17,12,.04)",
        glow: "0 0 0 4px rgba(0,196,106,.14)",
      },
    },
  },
  plugins: [require("tailwindcss-animate")],
} satisfies Config;
RULES FOR CLAUDE CODE
  1. Never put more than one accent (verification green) hue on the same screen. If everything is highlighted, nothing is.
  2. All numbers — phone numbers, codes, balances, prices, countdowns, order IDs — render in font-mono with tabular-nums.
  3. Use paper as page background, surface only for cards / dialogs / inputs. No gradients on surfaces.
  4. The wallet balance card is the one place the dark ink background is allowed in user UI. Don't generalize it.
  5. OTP code reveal uses dark background + vg/300 code text — it's the screen everything builds toward, treat it as the visual climax.
  6. Status uses badges + dot indicators. Never colored backgrounds on whole rows.
  7. Border weight: 1px always. Never use 2px or thicker borders for emphasis — use shadow or contrast instead.
  8. Sentence case for all UI labels. No title case. No emoji. No exclamation marks anywhere.

DEFINITION OF "VISUALLY DONE" FOR PHASE 1
  • Brand sans loaded (Aeonik or General Sans) + JetBrains Mono.
  • All four core screens render with paper background and the file-map components above.
  • Wallet card uses ink background + verification-green accent.
  • OTP reveal screen exists and is visually the most prominent block in the order detail page.
  • Country & service pickers use the two-column layout shown in the buy template.
  • Status uses pill badges with a pulsing dot for live states.
  • All numbers render in mono with tabular numerals.
  • Empty / loading / error states follow the three-tile pattern.
  • No gradient backgrounds, no emoji, no decorative iconography.
  • Only one accent hue per screen. If unsure, leave it out.
